# Building 3D View Implementation Plan

**Goal:** Add a 3D building mode derived from the existing clean SVG drawing set, with the pale model / tinted glazing / soft shadows presentation observed at https://easy-page-fly.lovable.app/.

**Architecture:** Parse wall rectangles, wall polygons, white opening masks, floor outlines, room polygons and stair metadata from the same `window.DRAWINGS` used by the 2D viewer. Register floors using corresponding rear walls; take storey heights from section checks. Split wall meshes around actual SVG opening masks. Build floor slabs with void/stair holes. Infer roof depth from plan outlines and elevation profiles. Keep controls/rendering separate from geometry conversion. Bundle Three.js and the model code locally so file:// and single-file offline usage work.

**Tech stack:** Existing HTML/CSS/JavaScript, Three.js, OrbitControls, polygon-clipping, esbuild (build only).

## Shared-data refactor

Both renderers now consume a canonical primitive tree. SVG is a derived serialization; semantic wall/window/door records reference elements instead of repeating shape coordinates. Room boundaries resolve from the same polygons. Section levels and named inferred parameters are centralized. The parser materializes this tree once per build, and the mesh layer has no separate floor-plan coordinates.

## Design decisions

- Keep the existing white UI, despite the reference's dark sidebar.
- Use a real orbitable mesh model, not an image or an unrelated prefab.
- Use source geometry for all wall positions/widths and openings. Undimensioned roof intersections, glazing profiles and stair fabrication details remain inferred, consistent with the existing audit.
- Do not add imaginary furniture or landscaping; the source has fixtures but no furnished room layout.
- No deployment or external upload is required; delivery remains local/offline.
